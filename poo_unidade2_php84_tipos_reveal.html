Ambiente PHP
para desenvolvimento

O objetivo é transformar “um arquivo solto” em “um projeto executável”.

PHP como runtimeCLI e Web

PHP não é só “arquivo dentro do servidor”.

O mesmo runtime pode executar scripts no terminal, responder requisições HTTP em desenvolvimento e compor aplicações web completas.

Na prática didática, usaremos dois modos: CLI para experimentos rápidos e servidor embutido para páginas e requisições locais.

php.iniconfiguração

php.ini é o painel de controle do runtime.

Ele define limites, extensões, exibição de erros e comportamento do ambiente. No CLI, o arquivo é lido a cada invocação; em módulos de servidor, normalmente é lido quando o servidor inicia.

Não vamos “tuná-lo” agora; vamos saber localizar e interpretar.

o que observar em aula

  • display_errors em desenvolvimento
  • error_reporting mais rigoroso
  • extension=... para recursos externos
  • date.timezone quando necessário

Primeira estruturamínimo profissional

De arquivo solto para projeto

catalogo-php/
├── public/
│   └── index.php        # ponto de entrada HTTP
├── src/
│   └── Produto.php      # código da aplicação
└── composer.json        # metadados + autoload

A pasta public/ é a vitrine.
src/ é o estoque.

Usuário acessa a vitrine. A lógica interna fica protegida fora da raiz pública.

por que isso importa?

  • uma entrada para a aplicação;
  • autoload carregado uma vez;

  • preparação para frameworks como Laravel.
Entrada externadesconfie

Regra de ouro: dado externo chega como suspeito

Formulário, URL, JSON, CSV e terminal não conhecem seu modelo de domínio.

Antes de usar, você precisa validar, converter e escapar saída.

$nome = $_GET['nome'] ?? 'aluno';

// saída HTML segura
echo htmlspecialchars($nome, ENT_QUOTES, 'UTF-8');

Tipos ajudam, mas não substituem validação de entrada.

Composerdependências e autoload

Composer é o “gerente de dependências” do PHP moderno.

Ele registra bibliotecas, scripts e regras de autoload. Mesmo sem instalar pacotes externos, ele já resolve um problema central: como encontrar classes.

Sem Composer: vários require_once. Com Composer: um autoload central.

composer dump-autoload

Autoloadsem mágica

O autoload parece mágica, mas é contrato

quando o PHP encontra

new App\Produto()

ele pergunta ao autoloader: “onde mora essa classe?”.

o Composer responde

App\ mora em src/

então carrega o arquivo correto no momento necessário.

A regra de ouro: namespace, nome da classe e caminho precisam conversar.

PSR-12legibilidade

Estilo não é frescura: é reduzir custo de leitura

PSR-12 estende e substitui a PSR-2 como guia de estilo para código PHP moderno.

  • padroniza abertura de arquivos, namespaces e imports;
  • define organização de classes e métodos;
  • facilita revisão, manutenção e trabalho em equipe.
<?php

declare(strict_types=1);

namespace App;

final class Produto
{
    public function __construct(
        private string $nome,
    ) {}
}

Base: PHP-FIG PSR-12.

Frase de impacto

Código é escrito uma vez e lido dezenas de vezes.
Ambiente e padrão existem para proteger a leitura.

Declaraçõesparâmetro e retorno

Contrato de função: o que entra e o que sai

sem contrato

function aplicarDesconto($preco, $percentual) {
    return $preco - ($preco * $percentual / 100);
}

com contrato

function aplicarDesconto(
    float $preco,
    float $percentual
): float {
    return $preco - ($preco * $percentual / 100);
}

A segunda versão informa intenção para humanos, IDE, runtime e ferramentas de análise.

Base: Manual do PHP — Type declarations.

strict_typeso detalhe que muda tudo

PHP pode converter por você. Nem sempre isso é bom.

modo coercitivo padrão

function dobrar(int $n): int {
    return $n * 2;
}

echo dobrar('10'); // pode converter

modo estrito no arquivo chamador

<?php

declare(strict_types=1);

echo dobrar('10'); // TypeError

Em aula: usar declare(strict_types=1); como padrão no topo dos arquivos PHP.

Base: Manual do PHP — Strict typing.

Base: Manual do PHP — propriedades tipadas desde PHP 7.4 e declarações em propriedades.

Nulosausência explícita

?Tipo: quando ausência faz parte do contrato

sem nulo

function nomeCurto(string $nome): string {
    return substr($nome, 0, 20);
}

com nulo explícito

function cupomAtual(?string $codigo): string {
    return $codigo ?? 'sem-cupom';
}

Não use null como “não pensei nisso”. Use quando “sem valor” for uma possibilidade real do domínio.

Union typesuma coisa OU outra

A|B: quando o domínio aceita alternativas

function formatarIdentificador(int|string $id): string
{
    return 'ID-' . $id;
}

Bom uso

Entrada realmente pode ser número ou texto.

Mau uso

Usar união para esconder indecisão de modelagem.

Intersection typesuma coisa E outra

A&B: o objeto precisa cumprir múltiplos contratos

interface Exportavel { public function exportar(): string; }
interface Auditavel { public function auditoria(): array; }

function enviarRelatorio(Exportavel&Auditavel $relatorio): void
{
    // precisa exportar e também gerar dados de auditoria
}

Interseção é útil quando a função depende de capacidades, não de uma classe específica.

Tipos especiaisintenção

mixed, void e never dizem muito sobre intenção

mixed

“Pode ser qualquer coisa”. Use pouco; exige cuidado.

void

“Executa uma ação e não retorna valor útil”.

never

“Não retorna nunca”: lança exceção ou encerra execução.

function falhar(string $mensagem): never
{
    throw new RuntimeException($mensagem);
}
Arraysponto crítico

array é poderoso, mas pouco específico

function total(array $produtos): float
{
    // array de quê?
    // quais chaves existem?
    // qual tipo de cada campo?
}

O tipo nativo array não informa a forma interna. Por isso, em projetos reais, combinamos:

  • objetos para dados importantes;
  • PHPDoc para listas e shapes;
  • PHPStan para checar contratos antes de executar.

Base: PHPStan — PHPDoc types e array shapes.

Enumsconjunto fechado

Quando os valores possíveis são conhecidos, use enum

enum StatusProduto: string
{
    case Ativo = 'ativo';
    case Inativo = 'inativo';
    case Esgotado = 'esgotado';

Enum troca “strings mágicas” por opções explícitas do domínio.

PHP 8.4novidades úteis para POO

PHP 8.4 reforça a modelagem de objetos

Property hooks

Permitem interceptar leitura/escrita de propriedades com lógica controlada.

Visibilidade assimétrica

Permite leitura pública e escrita mais restrita, como public private(set).

Essas features aproximam propriedades de contratos de domínio, reduzindo parte da cerimônia de getters/setters.

Base: PHP 8.4 release announcement e Manual do PHP — property hooks.

Property hooksvalidação no estado

Exemplo PHP 8.4: propriedade com validação

final class Produto
{
    public string $nome {
        set {
            if (trim($value) === '') {
                throw new InvalidArgumentException('Nome obrigatório');
            }
            $this->nome = $value;
        }
    }
}

Use como ferramenta de modelagem, não como desculpa para esconder regras confusas dentro de propriedades.

Visibilidade assimétricaleitura ≠ escrita

Objeto legível por fora, protegido contra alteração indevida

final class Produto
{
    public private(set) string $nome;

    public function __construct(string $nome)
    {
        $this->nome = $nome;
    }
}

Quem usa o objeto consegue ler $produto->nome, mas não consegue reescrever livremente.

Passo 3classe tipada

Produto como objeto, não como “array qualquer”

<?php

declare(strict_types=1);

namespace App;

final class Produto
{
    public function __construct(
        public string $nome,
        public float $preco,
        public int $estoque,
        public StatusProduto $status = StatusProduto::Ativo,
    ) {}

    public function precoFormatado(): string
    {
        return 'R$ ' . number_format($this->preco, 2, ',', '.');
    }
}

Passo 5renderização

public/index.php renderizando o catálogo

<?php

declare(strict_types=1);

require __DIR__ . '/../vendor/autoload.php';

use App\Produto;
use App\StatusProduto;

$produtos = [
    new Produto('Mouse sem fio', 89.90, 12),
    new Produto('Teclado mecânico', 249.90, 4),
    new Produto('Monitor 24"', 899.00, 0, StatusProduto::Esgotado),
];

foreach ($produtos as $produto) {
    echo '<p>';
    echo htmlspecialchars($produto->nome) . ' — ';
    echo $produto->precoFormatado() . ' — ';
    echo $produto->status->value;
    echo '</p>';
}
