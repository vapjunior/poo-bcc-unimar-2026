História

POO nasceu de uma necessidade de simular sistemas complexos

1960s

Dahl e Nygaard desenvolvem Simula no Norwegian Computing Center para descrever sistemas de eventos discretos.

Simula 67

Introduz conceitos como objetos, classes, herança, subclasses e procedimentos virtuais.

Fontes: ACM Turing Award; IEEE Milestones; PHP Manual. Ver referências ao final.
Por que isso importa?

A origem explica a ideia central

Objetos surgiram para representar entidades que existem, mudam e interagem ao longo do tempo.

Sem objeto

Você espalha listas, índices, parâmetros e funções por todo o programa.

Com objeto

Você cria unidades com nome, regra e responsabilidade: Produto, Carrinho, Pedido.

Analogia: um objeto é como uma peça de LEGO com encaixes definidos. Você não precisa saber como ela foi fabricada para usá-la corretamente.

Antes: código procedural

Quando dados e operações vivem separados

<?php
$produto = [
    'nome' => 'Teclado Mecânico',
    'preco' => 250.00,
    'estoque' => 10,
];

function aplicarDesconto(array $produto, float $percentual): array
{
    $produto['preco'] -= $produto['preco'] * ($percentual / 100);
    return $produto;
}

$produto = aplicarDesconto($produto, 10);

Funciona, mas a regra de desconto está fora do conceito Produto. Conforme o sistema cresce, regras ficam espalhadas.

Depois: objeto

Dados e comportamento passam a fazer parte da mesma ideia

<?php
class Produto
{
    public string $nome;
    public float $preco;
    public int $estoque;

    public function aplicarDesconto(float $percentual): void
    {
        $this->preco -= $this->preco * ($percentual / 100);
    }
}

$produto = new Produto();
$produto->nome = 'Teclado Mecânico';
$produto->preco = 250.00;
$produto->estoque = 10;

$produto->aplicarDesconto(10);

Atenção: esse ainda é um primeiro passo. Depois vamos proteger melhor as regras com encapsulamento.

Vocabulário essencial

Classe, objeto e instância não são sinônimos perfeitos

TermoIdeiaExemplo
ClasseDefinição do tipo: propriedades, métodos, constantes e regras.class Produto { ... }
ObjetoEntidade em memória, com identidade própria e estado atual.o produto “Teclado Mecânico” criado em execução.
InstânciaUm objeto específico criado a partir de uma classe.$teclado = new Produto();

Frase de impacto: classe é a receita; objeto é o bolo assado. A receita não alimenta ninguém — o objeto é o que existe durante a execução.

Classe como molde

Uma classe descreve o que todos os objetos daquele tipo têm em comum

Produto
Propriedades

Métodos

O molde não define o valor de cada produto. Ele define a estrutura possível e as operações válidas.

Por isso, uma boa classe comunica intenção: ao ler Produto, você entende o papel daquele conceito no domínio.

Tripé do objeto

Identidade, estado e comportamento

Identidade

O objeto continua sendo “ele mesmo” mesmo se seu estado mudar.

Estado

Valores atuais de suas propriedades: preço, estoque, status.

Comportamento

Métodos que alteram ou consultam o estado obedecendo regras.

Um objeto saudável não é apenas “um saco de dados”. Ele protege o próprio estado por meio de comportamento consistente.

Anatomia de uma classe

O que aparece dentro de class Produto?

<?php
class Produto
{
    public string $nome;
    public float $preco;

    public function aplicarDesconto(float $percentual): void
    {
        $this->preco -= $this->preco * ($percentual / 100);
    }

    public function precoFormatado(): string
    {
        return 'R$ ' . number_format($this->preco, 2, ',', '.');
    }
}

public string $nome cria uma propriedade tipada. public function cria um método. $this aponta para o objeto atual.

Propriedades

Propriedades representam estado — mas estado precisa de regra

<?php
class Produto
{
    public string $nome;
    public float $preco;
    public int $estoque;
}

O problema do acesso livre

Se tudo é público, qualquer parte do sistema pode fazer:

$produto->preco = -1000;
$produto->estoque = -50;

O objeto passa a aceitar estados impossíveis.

Métodos

Métodos expressam operações válidas no domínio

<?php
class Produto
{
    private int $estoque;

    public function reservar(int $quantidade): void
    {
        if ($quantidade <= 0) {
            throw new InvalidArgumentException('Quantidade inválida.');
        }

        if ($quantidade > $this->estoque) {
            throw new RuntimeException('Estoque insuficiente.');
        }

        $this->estoque -= $quantidade;
    }
}

Em POO, métodos devem contar uma história: o que esse objeto permite que façam com ele?

$this

$this é a forma do objeto falar de si mesmo

Dentro da classe

$this->preco
$this->estoque
$this->reservar(2)

“Este objeto aqui, nesta execução.”

Fora da classe

$produto->preco
$produto->reservar(2)

Uma variável externa aponta para um objeto específico.

Se a classe é o texto da peça, $this é o ator que está no palco naquele momento.

Criação de objetos

new cria uma instância em tempo de execução

<?php
$teclado = new Produto();
$mouse = new Produto();

$teclado->nome = 'Teclado Mecânico';
$mouse->nome = 'Mouse Gamer';

O código da classe

Existe antes da execução como definição.

O objeto

Existe durante a execução como entidade concreta em memória.

Identidade em PHP

A variável não contém o objeto inteiro: contém um identificador para acessá-lo

<?php
$a = new Produto();
$a->nome = 'Camiseta';

$b = $a;
$b->nome = 'Camiseta Premium';

echo $a->nome; // Camiseta Premium

No PHP, ao atribuir ou passar um objeto, as variáveis recebem uma cópia do identificador que aponta para o mesmo objeto — não uma cópia independente do objeto.

Base: PHP Manual — Objects and references.
Comparação

Duas variáveis podem apontar para o mesmo objeto

<?php
$a = new Produto();
$b = $a;
$c = new Produto();

var_dump($a === $b); // true: mesma instância
var_dump($a === $c); // false: instâncias diferentes

Para objetos, === pergunta: “é exatamente a mesma instância?”

Clonagem

clone cria outro objeto — mas cuidado com cópia rasa

<?php
$original = new Produto();
$original->nome = 'Caneca';

$copia = clone $original;
$copia->nome = 'Caneca Azul';

echo $original->nome; // Caneca
echo $copia->nome;    // Caneca Azul

O PHP faz uma shallow copy: propriedades que também apontam para objetos precisam de atenção em cópias profundas.

Base: PHP Manual — Object Cloning.
Construtores

Construtor coloca o objeto em estado válido desde o nascimento

<?php
class Produto
{
    private string $nome;
    private float $preco;

    public function __construct(string $nome, float $preco)
    {
        if ($preco <= 0) {
            throw new InvalidArgumentException('Preço deve ser positivo.');
        }

        $this->nome = $nome;
        $this->preco = $preco;
    }
}

$produto = new Produto('Teclado Mecânico', 250.00);

A mensagem é: “não existe produto válido sem nome e preço positivo”.

PHP moderno

Promoção de propriedades reduz boilerplate

Forma clássica

class Produto
{
    private string $nome;
    private float $preco;

    public function __construct(
        string $nome,
        float $preco
    ) {
        $this->nome = $nome;
        $this->preco = $preco;
    }
}

Com property promotion

class Produto
{
    public function __construct(
        private string $nome,
        private float $preco
    ) {}
}

Menos repetição. Mesma ideia: parâmetros do construtor viram propriedades do objeto.

Construtor com regra

Promoção não impede validação

<?php
class Produto
{
    public function __construct(
        private string $nome,
        private float $preco
    ) {
        if (trim($this->nome) === '') {
            throw new InvalidArgumentException('Nome obrigatório.');
        }

        if ($this->preco <= 0) {
            throw new InvalidArgumentException('Preço deve ser positivo.');
        }
    }

    public function preco(): float
    {
        return $this->preco;
    }
}
Encapsulamento

Encapsular é controlar como o estado pode mudar

Sem encapsular

$produto->preco = -10;
$produto->estoque = -5;

O sistema permite estados inválidos.

Encapsulado

$produto->alterarPreco(199.90);
$produto->reservar(2);

A mudança passa por uma regra do próprio objeto.

Encapsulamento não é esconder por esconder. É preservar a verdade interna do objeto.

Invariantes

Uma invariante é uma regra que deve continuar verdadeira

Produto

  • preço deve ser maior que zero;
  • estoque não pode ser negativo;
  • nome não pode ser vazio.

ContaBancaria

  • saldo não pode ficar negativo se não houver limite;
  • saque precisa respeitar regras;
  • depósito precisa ser positivo.

O bom objeto não apenas guarda dados: ele impede que o sistema conte mentiras sobre o domínio.

Property Hooks — PHP 8.4

PHP 8.4 aproxima propriedades de regras explícitas de acesso

<?php
class Produto
{
    public function __construct(
        public string $nome,
        private float $precoBase
    ) {}

    public float $precoComImposto {
        get => $this->precoBase * 1.12;
    }
}

Property hooks foram introduzidos no PHP 8.4 e permitem definir comportamento em operações de leitura e escrita de propriedades.

Base: PHP Manual — Property Hooks; PHP 8.4 Release Announcement.
Cuidado pedagógico

Property hooks não substituem pensar o modelo

Use para

Propriedades calculadas, validações pontuais e APIs mais expressivas.

Evite para

Transformar todas as regras de negócio em “mágica” escondida na leitura/escrita.

Ferramenta moderna não corrige modelo mal pensado.

Getters e setters

Não crie métodos mecânicos sem intenção

Anêmico: só expõe dados

$produto->setPreco(-10);
$produto->setEstoque(-5);
$produto->setNome('');

Expressivo: fala o domínio

$produto->alterarPreco(199.90);
$produto->reservar(2);
$produto->renomear('Teclado');

Um setter que não valida nada costuma ser apenas uma propriedade pública com passos extras.

Objeto anêmico

Quando a classe vira só uma tabela em forma de código

Modelando Produto

Comece com estado mínimo e regras essenciais

<?php
namespace App;

class Produto
{
    public function __construct(
        private string $nome,
        private float $preco,
        private int $estoque
    ) {
        if (trim($this->nome) === '') {
            throw new \InvalidArgumentException('Nome obrigatório.');
        }
        if ($this->preco <= 0) {
            throw new \InvalidArgumentException('Preço inválido.');
        }
        if ($this->estoque < 0) {
            throw new \InvalidArgumentException('Estoque inválido.');
        }
    }

    public function reservar(int $quantidade): void
    {
        if ($quantidade <= 0 || $quantidade > $this->estoque) {
            throw new \RuntimeException('Quantidade indisponível.');
        }

        $this->estoque -= $quantidade;
    }

    public function preco(): float
    {
        return $this->preco;
    }
}
Modelando ItemCarrinho

Uma classe pode representar uma relação

<?php
namespace App;

class ItemCarrinho
{
    public function __construct(
        private Produto $produto,
        private int $quantidade
    ) {
        if ($this->quantidade <= 0) {
            throw new \InvalidArgumentException('Quantidade inválida.');
        }

        $this->produto->reservar($this->quantidade);
    }

    public function subtotal(): float
    {
        return $this->produto->preco() * $this->quantidade;
    }
}

O item não é apenas quantidade: ele sabe calcular o subtotal daquela escolha.

Modelando Carrinho

Um objeto também pode guardar uma coleção de outros objetos

<?php
namespace App;

class Carrinho
{
    /** @var ItemCarrinho[] */
    private array $itens = [];

    public function adicionar(Produto $produto, int $quantidade): void
    {
        $this->itens[] = new ItemCarrinho($produto, $quantidade);
    }

    public function total(): float
    {
        return array_reduce(
            $this->itens,
            fn (float $total, ItemCarrinho $item) => $total + $item->subtotal(),
            0.0
        );
    }
}

Erro comum 1

“Classe é só uma forma de separar arquivo”

Não. Classes devem representar conceitos, tipos e responsabilidades. Separar arquivo sem separar responsabilidade só muda a bagunça de lugar.

Pior sinal

Classe chamada Funcoes, Utils, Manager fazendo tudo.

Melhor sinal

Classes com nomes do domínio: Pedido, Carrinho, Produto, Aluno, Matricula.

Erro comum 2

“Todo dado precisa de getter e setter”

Getters podem ser úteis para consulta. Setters sem regra podem quebrar a integridade do objeto.

<?php
$pedido->setStatus('pago');      // Quem validou pagamento?
$pedido->setTotal(-100);         // Total negativo?
$pedido->setItens([]);           // Pedido vazio depois de fechado?

Prefira métodos que expressem intenção: confirmarPagamento(), cancelar(), adicionarItem().

Erro comum 3

“Objeto é sempre melhor que função”

Não transforme POO em religião.

Função pode ser suficiente

Operação pura, simples e sem estado relevante.

Objeto faz sentido

Há estado, regra, identidade, ciclo de vida ou colaboração.

Boa engenharia é escolher a abstração que reduz complexidade, não a que parece mais sofisticada.

Entidades e Value Objects

Nem todo objeto tem o mesmo tipo de identidade

Entidade

Importa quem é. Pode mudar com o tempo mantendo identidade.

Pedido #1024, Aluno RA 123, Cliente ID 7.

Value Object

Importa o valor. Dois objetos com os mesmos valores são equivalentes.

CPF, Email, Dinheiro, Endereco.

Essa distinção ajuda a decidir mutabilidade, comparação e responsabilidade.

Exemplo: Value Object

Preço pode virar conceito, não apenas número

<?php
class Dinheiro
{
    public function __construct(
        private int $centavos
    ) {
        if ($this->centavos < 0) {
            throw new InvalidArgumentException('Valor não pode ser negativo.');
        }
    }

    public function somar(Dinheiro $outro): Dinheiro
    {
        return new Dinheiro($this->centavos + $outro->centavos);
    }

    public function formatar(): string
    {
        return 'R$ ' . number_format($this->centavos / 100, 2, ',', '.');
    }
}

Um objeto pequeno pode impedir muitos bugs de arredondamento, sinal e formatação.

Mutabilidade

Um objeto pode mudar — mas nem sempre deveria

Mutável

Carrinho muda quando adicionamos itens. Faz sentido: ele representa um processo em andamento.

Imutável

Email ou Dinheiro podem nascer válidos e nunca mudar. Para alterar, crie outro objeto.

Objetos imutáveis reduzem efeitos colaterais e facilitam raciocinar sobre o programa.

Critérios de qualidade

Como saber se a classe está bem modelada?

Bons sinais

  • nome vem do domínio;
  • tem poucas responsabilidades coesas;
  • protege invariantes;
  • métodos expressam ações reais.

Sinais de alerta

  • classe gigante;
  • muitos setters públicos;
  • estado público demais;
  • nome genérico: Manager, Helper, Utils.

Síntese

O que levamos da Unidade 3?

Ideia central

Objetos são unidades com identidade, estado, comportamento e responsabilidade.

PHP

Classes, propriedades, métodos, $this, new e construtores materializam o modelo.

Qualidade

Encapsulamento protege invariantes e reduz estados impossíveis.

Projeto real

Namespaces, Composer e PSR-4 deixam o código escalável desde o começo.

Frase final

Classes bem desenhadas são decisões pedagógicas do código

Elas ensinam ao próximo programador quais conceitos existem, quais regras importam e quais ações fazem sentido.

Quando o modelo melhora, o código deixa de ser apenas instrução e passa a ser comunicação.
